# MED3pa standalone app — python requirements
#
# This is the file the PACKAGED APP installs from: installRequiredPythonPackages()
# in main/utils/pythonEnv.js runs `pip install -r` against it inside the bundled
# python. pythonEnv/create_conda_env.sh uses the same file for dev environments.
# Anything added here ships to end users, so keep it minimal.
#
# Python version: every platform bundles the same CPython 3.12 standalone build
# (see PYTHON_VERSION in main/utils/pythonEnv.js). Everything pinned below
# resolves on it.
#
# Keep the format simple: one `name==version` per line. The app's own
# checkPythonRequirements() parses this file to decide whether the setup is
# complete, and it only understands `==` pins and `#` comments.
MED3pa==1.1.0a3

# checkpointer is deliberately NOT pinned here. MED3pa selects it itself, with a
# python_version marker (it is skipped entirely below 3.12), and pinning it from
# the outside is what produced the "unexpected keyword argument 'root_path'"
# failure when the pin disagreed with the API the library actually calls.

# --- MED3pa's own dependencies, pinned to the combination that resolves ---
# numpy is held at 1.26.4 because MED3pa requires <2.1.0. That in turn constrains
# scipy: an unpinned install pulls scipy 1.18, which requires numpy>=2.0 and
# contradicts MED3pa. scipy 1.11.4 is the newest release happy on numpy 1.26.
